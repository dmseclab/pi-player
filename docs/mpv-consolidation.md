# Consolidation increment 1 — 24 November 2026

The lab proved natural Chromium restoration and software-first MPV playback. Keep the existing player controller and graphical session. This increment shares the proven renderer flags between both experimental adapters, suppresses audio initialization only for muted assets, preserves audible playback options, and makes fresh installs and normal upgrades use the same additive OS dependency provisioning. No HTTP renderer route, service activation or browser behavior change is introduced.

Next integration boundary: reuse the existing scheduled playlist item IDs, resolve and validate the local catalog and immutable FD server-side, keep one kiosk-owned renderer with generation-scoped cancellation and bounded supervision. The browser must not send paths, arbitrary MPV flags or commands. Authenticate the actual kiosk control channel; loopback alone and same-UID processes are not independent security boundaries. Preserve fit/fill/stretch, audio, loop duration and non-loop EOF semantics; unsupported combinations remain Chromium. Keep Chromium visible until verified readiness; if cleanup cannot be verified, quarantine rather than launch another renderer. Distinguish actual presented frames from IPC progress. Validate lease expiry on reload/disconnect, asset replacement, stopped schedules and API restart before enabling. Existing experimental code remains disabled while safety coverage is consolidated, not deleted prematurely. 

Package rollback is additive: installed OS packages are retained; the application/data rollback is separate. Package and renderer profile regression tests are required; physical upgrade and rollback remain lab acceptance gates.

## Increment 2: lifecycle seam

Added a transport-independent single-slot lifecycle bridge and regression tests for owner replacement, generation fencing, startup deadlines, lease expiry, cancellation, and quarantine. This is not a live endpoint. The trusted transport must bind the real kiosk, supply revision-bound catalog grants, independent display/EOF/stall evidence, bounded renderer operations and whole-process cleanup, and drive tick independently of browser traffic. The bridge does not itself authenticate a browser or prove physical display readiness. No deployment or runtime activation.
